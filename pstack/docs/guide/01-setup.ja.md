# pstack をセットアップする

このページでは、プラグインをインストールし、pstack が使うモデルを選び、最初のタスクを実行します。セットアップはコマンド 1 つと短い対話だけです。

## プラグインをインストールする

Cursor のチャットで次を実行します。

```text
/add-plugin pstack
```

Cursor がプラグインのインストールを確認します。

Claude Code では、`/plugin marketplace add cursor/plugins` の後に `/plugin install pstack@cursor-plugins` を実行します。Claude Code ではプラグインコマンドにプレフィックスが付くため、このガイドの各コマンドは `pstack:` プレフィックスを伴います。たとえば `/pstack:setup-pstack` のようになり、モデルルールは `~/.claude/rules/pstack-models.md` に書き込まれます。それ以外の違いは [Claude Code アダプタ](../harness/claude-code.md) が扱います。

## モデルを選ぶ

次を実行します。

```text
/setup-pstack
```

[`/setup-pstack`](../../skills/setup-pstack/SKILL.md) はアクセス可能なモデルを検出し、推論予算を尋ね、各ロール（コード委譲、判断、レビューパネル）を示して、どうしたいかを尋ねます。質問に答えると、`~/.cursor/rules/pstack-models.mdc` という、すべての pstack スキルが読む小さなルールを書き込みます。

デフォルトは `large` 予算と同じです。コード、プロース、判断は Opus 5.5 を `xhigh` 推論で動かし、レビューパネルと swarm ワーカーは `high` で動かします。どのロールも `xhigh` を超えて動くことはありません。レビューパネルの外では、Fable 5.2 はあなたがタスク用に名指ししたとき、または同じブリーフに対する Opus 5.5 の 2 回の実行がチェックに失敗した後にのみ動きます。`medium` は各ロールを 1 段階、`small` は 2 段階下げ、どちらもトークン消費が減ります。

気になる部分だけ上書きします。ルールに行のないロールはそのスキルのデフォルトを保ちます。デフォルトに戻すには、そのロールの行を削除します。`/setup-pstack` を再実行しても、デフォルトと異なるモデルを持つロールはそのまま残ります。デフォルトが変更された場合でも、変更前に書かれたルールは `/setup-pstack` を再実行するまで古いデフォルトを保持します。再実行すると、認識できる古いデフォルトを置き換え、何を置き換えたかを伝え、それ以外のあなたの選択は保持します。認識できないピンを外すには、そのロールの行を削除するか、ファイルを先に削除してください。

Auto を使うとどうなるか気になるかもしれません。ロールを `inherit-parent` または `auto` に設定すると、pstack はサブエージェントの `model` フィールドを省略するので、サブエージェントは親チャットのモデルを継承します。どちらの値も同じ意味で、どちらもモデルスラッグではありません。パネルのロールの場合、値はリストであり、エントリごとに 1 つのサブエージェントが動くため、リストの長さがパネルのサイズを決めます。セットアップは `swarm workers` も構成します。これは各 `/swarm` ワーカーのデフォルトモデルで、race が各 arm のモデルを指定しない限り使われます。

## 検証オファーを受け入れる、あるいは断る

セットアップの最後に、`/setup-pstack` はプロジェクト内でアプリの挙動を証明する方法、`verify-*` スキルか既存のハーネスを探します。どちらも見つからなければ、1 度だけ [`/create-verification-skill`](../../skills/create-verification-skill/SKILL.md) で生成するオファーを出します。

はいと答えると `.cursor/skills/verify-<app>/` を書き、ユーザーと同じようにエージェントがあなたのアプリを操作できるプロジェクトローカルなスキルを作ります。引き渡す前にそのスキルが機能することを 1 度証明します。いいえと答えるとセットアップは先に進みます。`/create-verification-skill` はいつでも自分で実行できます。詳細は [検証して出荷する](./06-verify-and-ship.md#create-a-project-verification-skill) にあります。

pstack が初めてなら、はいと答えてください。自分で作業を確認できるエージェントは、チェックが通るまで動き続けます。確認できないエージェントは、結果をすべてあなたに手作業でチェックさせます。このガイドの中で、検証スキルが最も費用対効果が高いものです。

次に、プロジェクトにまだない場合、セットアップは [`/create-formal-verification-skill`](../../skills/create-formal-verification-skill/SKILL.md) で形式検証スキルを生成するオファーを 1 度出します。テストは誰かが書こうと思いついたケースをチェックします。形式検証スキルは、あなたのコードの 1 つの重要な性質（「ジョブは一度に二度実行されない」など）を、宣言された範囲内の全ケースでチェックします。並行処理、リトライ、状態機械、パーサが絡み、バグが高くつき、テストが壊れるケースに届きにくいコードがあるときは、はいと答えてください。そうでなければいいえと答え、状況が変わったら後で実行します。詳細は [検証して出荷する](./06-verify-and-ship.md#prove-a-property-with-a-formal-verification-skill) にあります。

セットアップ後は新しいチャットを開始してください。モデルルールは新しいセッションに適用されます。

## コストを抑える

pstack はサブエージェントとレビューパネルに追加のトークンを使います。それが厳密さの代償です。使用量を減らすには次のようにします。

- `/setup-pstack` を再実行し、より小さな推論予算やより安価なモデルを選ぶ。メインチャットには強力なモデルを置き、コードロールには安価で高速なモデルを置く分け方が良いでしょう。
- ロールを `auto` または `inherit-parent` にして、チャット自身のモデルで動かす。
- パネルのリストを短くする。各エントリが 1 つのサブエージェントを動かします。
- `/poteto-mode` は厳密さが必要な作業のために取っておく。小さく自明な編集には必要ありません。

## 最初のタスクを実行する

本物だが小さなものを選び、同僚に説明するように説明してください。

```text
/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.
```

todo リストを見てください。最初の項目は、マッチしたプレイブック（このプロンプトでは Feature プレイブック）のステップがコピーされたものです。

ここからは通常のフォローアップを打ち込めます。チャット全体で `/poteto-mode` を有効にしたまま使いたい場合は、`/` メニューから選択する際に Enter ではなく Option+Enter（Mac）または Alt+Enter（Windows）を押してください。すると [Custom Mode](https://cursor.com/docs/skills#using-a-skill-as-a-custom-mode) になり、あなたが終了するまで毎ターンコンテキストに残ります。Custom Mode は Agents Window と CLI で利用できます。通常の Enter はスキルを 1 つのメッセージに付けるだけなので、チャットが進むにつれて薄れていきます。
