# フィーチャーマップ例

Benny が再現する可能性があるユーザー向けの機能をすべてマッピングする。アプリを操作する前に、該当するセクションを読むこと。このマップはユーザー視点で保つこと。内部実装や現行のコードパスは、ここで固定化せず、実行時に発見する。

このファイルを `.cursor/automations/benny/` の外、例えば `.cursor/benny/feature-map.md` にコピーし、`control.feature_map_path` をそのコピーに向けること。パックの更新がコピーを上書きしてはならない。

## 仮想例

これらの機能は架空のタスクアプリに属する。例であって、Benny に必須の機能ではない。

### サインイン

ユーザーがタスクアプリに入れるようにする。

#### ユーザーがそこへ到達する方法

- アプリを開き、`Sign in` を選ぶ。ショートカットなし。

#### コントロールアダプタによる操作方法

- `open_app`、`click Sign in`、`fill credentials`、`click Continue` でアイテム一覧が開くこと。
- 使い捨てセッションからサインアウトしてリセットする。

#### 安定セレクタ

- ボタン `Sign in`、テキストボックス `Email` と `Password`、`data-component="sign-in-form"`

#### 実行する状態

- Default、focus-visible、submitting、disabled、loading、error

#### 事前条件とセットアップ

- 使い捨てアカウントと利用可能な認証サービス

#### 証拠とクロスチェック

- ランディングページからアイテム一覧までを録画する。読み取り専用のセッション状態をチェックする。

#### 落とし穴

- マーケティングページは誤ったサーフェス。認証サービスの欠如はブロック要因。

### アイテム一覧と詳細

ユーザーがアイテムを閲覧し、1 つ開けるようにする。

#### ユーザーがそこへ到達する方法

- `Items` タブを開き、行を選ぶ。

#### コントロールアダプタによる操作方法

- `select_tab Items` と `click <fixture item>` でその詳細が開くこと。
- 詳細を閉じ、選択を解除してリセットする。

#### 安定セレクタ

- タブとリスト名 `Items`、フィクスチャ名で特定される行、`data-component="item-detail"`

#### 実行する状態

- Loading、empty、error、selected、open、expanded

#### 事前条件とセットアップ

- 名前付きフィクスチャアイテム、読み取り権限、利用可能なアイテムサービス

#### 証拠とクロスチェック

- 選択と一致する詳細タイトルを示す。選択アイテム ID をチェックする。

#### 落とし穴

- 検索結果は似ていても、別のパスを使う可能性がある。

### アイテムエディタ

ユーザーがアイテムを新規作成または編集できるようにする。

#### ユーザーがそこへ到達する方法

- 詳細から `Edit` を選ぶか、リストから `New item` を選ぶ。

#### コントロールアダプタによる操作方法

- `click Edit`、`fill <field>`、`click Save` で詳細が更新されること。
- フィクスチャを復元してリセットする。

#### 安定セレクタ

- ボタン `Edit`、`New item`、`Save`、フォーム `Item editor`、ラベル連携のフィールド

#### 実行する状態

- Default、focus-visible、dirty、validating、disabled、saving、error、success

#### 事前条件とセットアップ

- 編集可能なフィクスチャ、書き込み権限、利用可能な保存サービス

#### 証拠とクロスチェック

- フィールドの変更が更新後の詳細に反映されることを示す。保存されたアイテム値を読み取り専用でチェックする。

#### 落とし穴

- フォーム状態を注入しない。読み取り専用の詳細フィールドはエディタではない。

### 設定

ユーザーが個人設定を変えられるようにする。

#### ユーザーがそこへ到達する方法

- プロフィールメニューを開き、`Settings` を選ぶ。

#### コントロールアダプタによる操作方法

- `open_menu Profile`、`click Settings`、`toggle <preference>` でコントロールが更新されること。
- 開始時の設定に戻してリセットする。

#### 安定セレクタ

- ボタン `Profile`、メニュー項目 `Settings`、領域 `Settings`、目的を表す設定属性

#### 実行する状態

- Closed、open、selected、focus-visible、disabled、loading、error

#### 事前条件とセットアップ

- サインイン済みのテストアカウント、既知の設定、利用可能な設定サービス

#### 証拠とクロスチェック

- メニューパスと最終的なコントロール状態を示す。設定値を読み取り専用でチェックする。

#### 落とし穴

- OS の設定画面は別のサーフェスである。

## 網羅性チェックリスト

- 再現可能なユーザー向け機能ごとにセクションがある。
- 各セクションがユーザーパス、アダプタアクション、リセット方法を記している。
- セレクタはロール、名前、ARIA、安定したコンポーネントマーカー、または目的を表す属性を使っている。
- 生成クラスや DOM 位置をセレクタに使っていない。
- 該当するインタラクション、ローディング、空状態、エラー、選択、展開状態がカバーされている。
- 認証、フィクスチャ、権限、フラグ、サービスが明示されている。
- スクリーンショット、動画、裏付けクロスチェックの要件が明示されている。
- 誤ったサーフェス、行き止まり、安全な環境の読み替えが列挙されている。
- 実装詳細は実行時に発見するものとして残されている。
