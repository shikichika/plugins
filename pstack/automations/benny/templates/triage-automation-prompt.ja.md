# トリアージオートメーションのプロンプト

> コピー済みセットアップワークフロー用の素材。`automate` がオートメーションを動かすリポジトリにコピー済みパックがコミット済みであることを確認した後に、このインテントを組み込み `automate` のドラフトへ言い換えて反映する。

この実行では `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読み、従うこと。

構成ソース。このリポジトリ相対パスは、同じターゲットリポジトリにコミット済みである場合にのみ含めること。それ以外では、設定された値を言い換えて含める。プラグインソースやキャッシュのパスは絶対に使わないこと:

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成時のインテントでは、これを設定済みソース Slack チャンネルの新規トップレベル報告として記述すること。

ソースチャンネルとルートスレッドのタイムスタンプは不変として扱うこと。いずれかが欠けている、あるいは構成と一致しない場合、投稿やイシュートラッカーへの書き込みなしに停止すること。

コミット済みのオペレーショナルファイルが、分類、添付レビュー、原因追跡、ルーティング、重複排除、トラッカー書き込み、最終判定を所有する。進捗メッセージは投稿しないこと。ソースチャンネルにルートメッセージを投稿しないこと。

Slack に投稿するのはコーディネータのみ。委譲されたワーカーは必ず読み取り専用で、発見事項のみを返し、すべての Slack 書き込みアクションを明示的に禁じられていること。

1 件の判定は、設定済みマーカーのいずれかちょうど 1 つで締めくくること:

```text
[benny:bug]
[benny:performance]
[benny:other]
```

bug または performance のマーカーには `tracker=<URL>` を追加してよい。
