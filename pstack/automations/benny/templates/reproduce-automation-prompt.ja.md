# 再現オートメーションのプロンプト

> コピー済みセットアップワークフロー用の素材。`automate` がオートメーションを動かすリポジトリにコピー済みパックがコミット済みであることを確認した後に、このインテントを組み込み `automate` のドラフトへ言い換えて反映する。

この実行では `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読み、従うこと。

構成ソース。このリポジトリ相対パスは、同じターゲットリポジトリにコミット済みである場合にのみ含めること。それ以外では、設定された値を言い換えて含める。プラグインソースやキャッシュのパスは絶対に使わないこと:

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成時のインテントでは、これを設定済みソース Slack チャンネルの新規トップレベル報告として記述すること。設定済みのリポジトリ、デフォルトブランチ、イシュートラッカー、コントロールアダプタ、フィーチャーマップ、ドラフトプルリクエスト作成能力を含めること。

ソースチャンネルとルートスレッドのタイムスタンプは不変として扱うこと。いずれかが欠けている、あるいは構成と一致しない場合、投稿せずに停止すること。

設定済みのトリアージ identity からこのスレッドでの設定済みトリアージマーカーを待つこと。`[benny:bug]` または `[benny:performance]` の場合のみ処理を進めること。

再現を試みる前に、設定済みのコントロールアダプタのスキルを要求すること。実 UI を通じて、決定的な症状をそのまま 2 回再現すること。既存のプルリクエストやコミットは上書きせずに検証すること。範囲を限定した修正を試みるのは、再現が確認され、オペレーショナルファイルの修正ゲートを通過した後にのみとすること。

Slack に投稿するのはコーディネータのみ。子プロンプトは `SendSlackMessage`、`PostToSlack`、`chat.postMessage` およびその他すべての Slack 書き込みを禁じること。子は発見事項のみ返すこと。

ソースチャンネルにルートメッセージを投稿しないこと。
