# レバーを作れ

作業が自明でないときは、手作業ではなく、それを行うツール（codemod、スクリプト、ジェネレータ、または再実行可能なチェック）を構築する。基準は反復回数ではなく自明さである。ツールを省いてよいのは、明らかに自明な2〜3件の編集のみ。

- 最初の1単位を手作業で行い、その後ツールを構築し、その1単位でツールを再実行して証明する。再実行しても安全であるようにする。
- 決定論的なツールはファンアウトに勝る。ファンアウトする場合は、レシピ、検証契約、フェンスを1つのスキルとして書き、委任先はそれを読むだけで編集できないようにする。
- この原則を適用するとファイルが生まれる。差分にスクリプト、codemod、ジェネレータ、または委任用スキルがなければ、適用していないということ。作業がセッションを越えて残るなら、コミットする。
- 仕事を行う、または証明する最小のスクリプトを作れ。決してフレームワークにはしない。
