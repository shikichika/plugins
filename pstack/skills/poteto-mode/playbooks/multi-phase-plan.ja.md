### マルチフェーズまたはマルチ PR のプラン

**あなたが所有するのはプランであり、コードではない。プランとは、オーナーがボックスごとに実行し、オペレーターが証跡から監査するチェックリストである。** プランが成果物だ。実装してはならない。

1. 変更が 1〜2 ファイルで、アプローチが明白ならプランは省略する。そう宣言して停止する。
2. 書き始める前に、`playbooks/prototype.md` に従ってプロトタイプで未解決の疑問を片付ける。オペレーターに尋ねるのは、どの実行でも決着のつかないプロダクトや好みの判断についてのみ。
3. プランファイルを書く。冒頭には、変更内容、着地順の PR id、依存グラフ（どの PR がトランクから独立して分岐するか、どれがどれを待つか、各 PR が触れうるファイル）を記す。その後、PR ごとに 1 セクション。1 PR = それ自身の証跡を持つ 1 つの変更（**sequence-verifiable-units** の原則スキル）。各セクションには、依存先、編集するファイル、構築する唯一の変更、確認できる結果、検証内容のチェックボックスを置く。
4. テストだけでは検証として不十分。PR が検証済みと言えるのは、ユニット、ライブ、パフォーマンスのボックスがすべてチェックされたときだけだ。ライブボックスは、具体的なシナリオと合否述語で実際のサーフェスを動かす。パフォーマンスボックスは、メトリック、プローブ、最初に計測したトランク基準値、失格ラインとなる数値を明示する。インタラクションを変更する PR は、マージ前にオペレーターのレビューを待つ。
5. プランのパスを返して停止する。実行はオペレーターの明示的な go で開始する。

**返信:** プランのパス、依存関係とレビューゲート対象を含めた PR id、未証明のまま残ったもの。
