### Autonomous run

**あなたが終了条件を所有する。done を定義し、停止せずそこへ駆動する。**

1. 最初のイテレーションの前に、終了条件をチェック可能な述語として明記する (テストがグリーン、repro が修正された、N 個のすべての PR がマージされた、pixel-diff がゼロ)。
2. Cursor の `/loop` コマンド (pstack スキルではなくビルトイン) を使って起動メカニズムを選ぶ。監視するイベント (CI、マージ、ref の進行) にはそのイベントであなたを起こすウォッチャーサブエージェントを割り当て、長い時間ベースのハートビートをフォールバックとして使用する。イベントがない場合は、結果を再チェックする価値があるときに合わせた固定間隔のハートビートを使用する。Subagents セクションに従って、各サブエージェントの推論レベルをジョブに合わせて選ぶ。
3. 各イテレーションは、証拠が正当化する最小の変更を行い、述語に対して検証し、前進したらコミットし、役に立たなかった変更を破棄する。「役に立つかもしれない」ベルトとサスペンダーは、残さず、戻す。
   **sequence-verifiable-units** 原則スキルで作業を順序付け、最後にチェックをバッチ化する代わりに次の前に各ユニットを検証する。
4. ゴールをサポートする実行中の発見はあなたのものである。壊れたスキル、関連バグ、不安定な検証器、レビューノイズ、ツール障害、孤立したフォローアップ、修正可能なドリフトを poteto-mode で自分で対処する。帯域外の修正はそれら自身の PR に入れる。可逆な作業を人間のために駐車したり `AskQuestion` を使用したりしない。不可逆なアクション、実験で解決できない真の製品または嗜好の呼び出し、または本当の行き詰まりのみを表面化する。述語をメインドライブとして保ち、各サイド修正の後にそれに戻る。
5. **show-me-your-work** スキルで各イテレーションをチェックポイントし、何が変わったか、述語が動いたかを 1 行にする。
6. 述語が満たされたら停止する。プラトーは停止ではないので、続けて、それを越えるためにアプローチをピボットする。回転させるのではなく本当の行き詰まりを表面化し、勝利を宣言するために述語を緩めない。

**返信:** 終了条件、実行したイテレーション、何がランドしたか、何が破棄されたか、最終述語状態。
