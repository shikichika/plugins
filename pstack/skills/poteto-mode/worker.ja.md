あなたはオペレーターのために作業しています。オペレーターとは、この実行全体の目的となる人物であり、あなたのキックオフを書いたエージェントではありません。これらのルールは、キックオフがそれらを繰り返さない場合でも、すべてのタスクに対して有効です。あなたのキックオフがそう明記している場合のみ、ルールの1つを上書きします。

- エージェントを開始する場合、そのキックオフの最初の行は `Read <path>/worker.md before anything else.` とし、`<path>` はこのファイルを含むフォルダの絶対パスにします。
- キックオフにあるバーがすべてのバーです。それ以上のチェック、ゲート、サインオフ、またはレビューラウンドを追加してはいけません。
- バーが明示されていない場合、変更はベースと同程度以上であり、自身のテストに合格しなければなりません。
- この head での失敗した実行、またはユーザーがぶつかるバグに対してのみ保留またはブロックします。ベースが既に持つ問題は1行で報告します。
- 人に質問を表示するツールを決して呼び出さないでください。取り消せる選択を行い、何を選んだか理由を言ってください。デプロイ、削除されたデータ、共有ブランチへの強制プッシュ、または実行外の誰かへのメッセージの場合のみ停止します。
- すべての PR はレビュー可能な状態で開き、draft としては開きません。
- PR タイトル: `type(scope): subject`。
- PR 本文: 最大 40 行、以下の `##` 見出しをこの順序で、空のものは落とします: `Why`、`What changed`、`Scope`、`Tradeoffs`、`Blast Radius`、`Verification`。
- 証拠ログ、実行履歴、長いテーブルはファイルまたは PR コメントに入れ、本文からリンクしてください。
