# Swarm

## 開始

何かを起動する前に、各フェーズごとに 1 つのエントリを持つ todolist を開く。

1. Frame
2. Fan out
3. Aggregate
4. Report

## フェーズ A: Frame

1. 完了述語と、swarm が返すべき成果物またはレポートを定める。
2. 形式を選ぶ。スライスに分割する、同一のブリーフで N ワーカーをレースさせる、または両者を混ぜる。レースまたは混合形式の場合、スポーン前に `first pass`、`rank all`、`best-of` のいずれかを宣言する。
3. `~/.cursor/rules/pstack-models.mdc` の `swarm workers` の行からワーカーモデルを選ぶ。このルールやその行がない場合は `claude-opus-5-5-high-fast` を使う。`auto` または `inherit-parent` の場合は `model` を省略し、ワーカーが親モデル上で動作するようにする。Task ツールがスラッグを拒否した場合、デフォルトを使用し、その旨を述べる。デフォルトも拒否された場合、エラーメッセージから同じファミリーで最も近い有効なスラッグを使う。モデルレースの場合、各アームのモデルを事前に指定する。各サブエージェントの推論レベルは、**poteto-mode** スキルのサブエージェントセクションに従い、ジョブに応じて選ぶ。
4. 各ワーカーに書き込み用の独自の出力を与える。ワーカーがコミットを検証または計測する際、各ブリーフは正確な SHA を指定する。計測ブリーフは手法（サンプル数、1 サンプルの定義、順序）も指定する。ワーカーは結果に両者を記録する。

## フェーズ B: Fan out

`subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`、そしてステップ 3 のモデル（`auto` または `inherit-parent` の場合は未設定）を指定し、1 つのメッセージで N 個のワーカーをすべてスポーンする。`environment: "local"` を使うのは、ワーカーがユーザーのコンピュータ上のものにアクセスする必要がある場合のみとする。

ワーカーがデフォルトでないプッシュ済みブランチから開始する必要がある場合は、`cloud_base_branch` を渡す。

各ブリーフは単独で成立する。ゴール、スコープ、正確なスライスまたはレースアーム、検証方法、報告事項を含める。レポートには `PASS`、`ISSUES`、`BLOCKED` のいずれかを証跡とともに用いる。欠陥を証明できるワーカーは `ISSUES` を報告し、最初の 1 件だけでなく証明できるすべての問題を列挙する。

ワーカーが脱落した場合、N-1 で進め、その旨を記録する。

## フェーズ C: Aggregate

ターミナル結果を読む。ブリーフが指定した SHA と手法を記録していない結果は破棄し、そのワーカーを 1 回再スポーンする。2 度目の欠落後は、ギャップとして記録する。ギャップはパスとしてカウントされない。カバレッジでは、必須の各スライスに結果が必要である。レースでは、事前に宣言した選択ルールを適用する。first pass、rank all、best-of のいずれかを使う。ワーカーの生ダンプを貼り付けてはならない。

## フェーズ D: Report

結果テーブル、問題の一行要約、ギャップまたは脱落、使用した場合はレースルールを含む、統合されたチャット内レポートを 1 つ返す。
