# TypeScript のベストプラクティス

まず **type-system-discipline** の原則スキルを適用する。

| ルール | 概要 |
|------|---------|
| 判別可能ユニオン | バリアントは `kind` のリテラル判別子でモデル化し、不可能な状態を表現できないようにする。オプショナルフィールドの詰め合わせは使わない。 |
| ブランド型 | プリミティブを `& { readonly __brand: "X" }` でブランドし、混同を防ぐ。境界で一度だけ検証する。ブランドは検証する型ガード（`input is AgentId`）から生まれ、決して `as` から生まれない。 |
| 構成的モデリング | 不正な値が構成できないような形状にする。非空には `[T, ...T[]]`、偶数長には `[T, T][]`、範囲には `start` と `duration` を使う。実行時ガードでも、refinement 型への願いでもない。 |
| 最も単純な全域型 | その上のすべての操作が全域である限り `T[]` を保つ。緩い型が `!`、キャスト、または「起こらないはず」の throw を強いる箇所でのみ `NonEmpty<T>` に強化する。 |
| `unknown` を `any` より優先 | 外部データは `unknown`。 |
| ガードの前にスキーマ | 手書きでプロパティ単位の型ガードを書く前に、リポジトリの実行時スキーマライブラリを使い、スキーマから型を導出する（例えば `z.infer`）。 |
| `as` キャストの禁止 | すべての `as` は待機中の実行時クラッシュである。キャストは検証後にのみ行う。 |
| 絞り込みの階層 | 判別子による switch > `in` 演算子 > `typeof`/`instanceof` > ユーザー定義型ガード > `as`。 |
| 型ガード | 主張を実際に検証しなければならない。嘘をつく型ガードは `as` より悪い。安全だと名乗る裏でバグが隠れるからである。名前は `isX` や `hasX` にする。 |
| 網羅性 | default アームにインラインで `const _exhaustive: never = x;` を置く。新しいバリアントが追加されたときにコンパイラがエラーを出す。 |
| `satisfies` を `as` より優先 | リテラル型を広げずに値を検証する。 |
| 境界での検証 | データが入ってくる境界で、名前付きドメイン型にパースする。`Record<string, unknown>`（どんな綴りであれ）はそのパースで終わる。内部では型を信頼する。**boundary-discipline** 原則スキルを参照。 |
| スキーマ由来の型 | 新しいインターフェースを宣言する前に、`Pick`/`Omit`/`Parameters`/`ReturnType`/`Awaited`/`typeof` に手を伸ばす。 |
| オブジェクト引数 | 位置ではなくオブジェクトで渡し、引数の順序を自己文書化する。ホットパス（毎フレームレンダリング、トークナイザ、パーサ）ではスキップする。 |
| 実テスト | 実行できるものはモックしない。フレームワークの実テストプリミティブとリーク/disposable チェックを優先し、UI は実ビルドで検証する。ローカルで実行できないものだけモックする。 |
| 構造化テレメトリ | 構造化ロガーの診断を優先し、ID からデバッグできるだけの文脈を持たせる。出荷コードに `console.log` を入れない。 |

例は `references/patterns.md` を参照。
