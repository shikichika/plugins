# 共有状態をシリアライズする前に分離せよ

並行するアクターが同じファイル、ブランチ、キー、オブジェクトに書き込む可能性があるとき、まず彼らが1つの共有オブジェクトを必要としているのか、独立した事実を公表しているだけなのかを問え。デフォルトでは、各アクターに固有のファイル、キー、ブランチ、または状態ディレクトリを与え、状態を読み取る場所でのみマージせよ。2人のワーカーがそれぞれ自分のフィールドを1つの `state.json` に書き込むのは、依然として共有変更である。

共有書き込みターゲットが1つであることが本当に不変条件である場合にのみ、アクセスを構造的にシリアライズせよ（ロックファイル、単一ライター、逐次フェーズ、compare-and-swap）。指示は並行性制御ではなく、「ロックが必要だ」はまず疑うべきにおいである。
