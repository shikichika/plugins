# Show me your work

1 つの正式なログを保持する。

## フォーマット

単一の TSV ファイル、意思決定ごとに 1 行。セルは単一行を保つ。証拠はプロースではなくポインタ。

クリーンなログを開始するために `references/decision-log-template.tsv`（ヘッダー行）をコピーする。カラム:

- **ts.** ISO8601 タイムスタンプ。
- **phase.** フェーズまたはワークストリーム。
- **decision.** 選択または行われたこと、1 行。
- **why.** 平易な言葉での理由。原則が駆動した場合、専門用語タグではなく平易に述べる。
- **evidence.** それを証明するリンクまたはパス: コミット SHA、PR 番号、`file:line`、または成果物、トレース、スクリーンショットパス。決して段落ではない。
- **result.** 結果または述語の状態: `tests green`、`reverted`、`pixel-diff 0`、`INCONCLUSIVE`、`open`。

例、レビューワーが一目で読めるよう平易に述べる。

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	counted the work first, about 100 components and roughly 75 hours	wanted to know the size before starting a long run	commit 3a9f1c2	found 5 things to sort out before starting
2026-05-24T09:40:00Z	harness	took screenshots of the old version before changing anything	so we can compare old against new and catch any visual change	scripts/snapshot.sh, baseline/	saved 120 reference screenshots
2026-05-24T11:15:00Z	widget	moved the widget styles over without changing how it looks	keep the change small and the result identical	commit 7c21e0a, pixel-diff 0	looks identical, tests pass
2026-05-24T12:30:00Z	widget	threw out a helper's work because its screenshots were blank	checked the real files instead of trusting its summary	worktree reset	reverted, tightened the instructions for next time
```

## 行をログに記録する

チームメイトに何をしたかを伝えるように、各エントリを書く。平易な言葉、具体的なアクション、AI 用語や抽象的な専門用語なし（**unslop** スキルはログのテキストにも適用される）。

ヘルパー `scripts/log.sh <logfile> <phase> <decision> <why> <evidence> <result>` を使う。`ts` をスタンプし、最初の使用時にヘッダーを書き、はぐれたタブ／改行を剥がし、`=`、`+`、`-`、または `@` で始まる任意のセルに単一引用符をプレフィックスする。生の `printf` で行を追加することもできるが、セルが生成された、またはユーザーが提供したテキストから来る場合、それらと同じバイトに注意する。

意思決定ポイントとチェックポイントをログに記録し、すべてのアクションではない: 選ばれたフォーク、検証結果付きの完了したユニット、トリガー付きのピボットまたはリバート、浮上したブロッカー、修正されたゲート。ループ実行では、イテレーションごとに 1 行。些細なものや自明なものはスキップする。

実行とは、1 つのエージェント会話であり、後のターンとその任意の要約を含む。ピックアップ、置き換えエージェント、または新しいチャットは新しい実行を開始する。実行が既に行がある場所にログに追加するとき、その最初の行はフェーズ `start` を持ち、別の実行の `start` 行の後の最初の行も同様。したがって後のターンでログに戻る実行は、まずログの最後の行を読んで、別の実行が書いたかどうかを確認する。`start` 行は、この実行が書いていない前の行の `ts` 範囲を名付け、その証拠はこの実行（そのエージェント ID など）を名付ける。他のことにフェーズ `start` を使わない。

## 場所

デフォルトではログは作業成果物であり、コミットされない。作業ディレクトリで `decisions.tsv`、または複数の取り組みが同時に実行される場合は `.audit/<task-slug>.tsv` に保持し、git から除外する。

レビューワーが結果を信頼するために軌跡が必要なほど作業が野心的な場合のみコミットする。

## ルール

- 追加専用。間違った呼び出しは、それに取って代わる新しい行を得る。履歴を編集または削除しない。
- 手作りの 1 回限りのものより、コミットされたスクリプトによって生成された証拠を優先する（**encode-lessons-in-structure** 原則スキル）。

## トランスクリプトに対するログの監査

実行の最後、引き渡し前に、ログが真実を語ったか確認する。アクティブなワークスペースの `agent-transcripts/` ディレクトリの下でこの実行のトランスクリプトを読む（システムプロンプトがパスを名付ける）。`~/.cursor/projects/*/` 全体を glob しない。それは無関係なプライベートチャットを読む。実際に起こったことに対してこの実行の行を辿る。それぞれの連続は、この実行の `start` 行の 1 つから始まるか、この実行がログを作成した場合は最初の行から始まり、別の実行の次の `start` 行で終わる:

- すべての行が実際の意思決定またはアクションにマップされるか確認する。
- 各行の証拠が解決し、行が主張するものを示すか確認する。
- 作業を形作ったが記録されていないフォーク、ピボット、または放棄されたアプローチはギャップである。追加する。

ストーリーではなく、ログを修正する。監査は、発明された行でも、行を決して編集または削除しない。行が実際の意思決定や実際のアクションを記録しない、またはその主張や証拠が間違っている場合、実際に起こったことと解決するポインタでそれに取って代わる行を追加する。この監査は、この実行の連続の外の行をチェックしない。この実行自身の作業がそのうちの 1 つが間違っていることを示す場合、他の間違った呼び出しと同様にそれに取って代わる。

## 軌跡のクロスモデルレビュー

引き渡し前に、作業を行ったものとは別のベンダーのモデルでサブエージェントを起動する。セルフレビューは代替ではない。サブエージェントは監査証跡と実行のトランスクリプトを読み、ユーザーが注意すべきことをフラグする。作業のやり直しではなく、何が最適でないかリスクがあるかのスキャン。**poteto-mode** スキルの Subagents セクションに従って、各サブエージェントの推論レベルをジョブに合わせて選ぶ。

- 弱いまたは不在の証拠でログに記録された意思決定。
- スキップされた、またはトランスクリプトに証明なしに主張された検証ステップ。
- 後から見るとリスクがあるように見える選択（早すぎる、スコープクリープ、症状を覆い隠す）。
- カジュアルなスキミングではユーザーが見逃すギャップ。

軌跡を生成した実行のすべての返信は「Attention」セクションで終わる。レビューワーのモデルを独立した行で先頭に置き（`reviewed by <model>`）、次に特定の行や瞬間を指す各フラグをリストする。「No flags」は有効な値である。モデル名はそうではない。

## 軌跡のレビュー

上から下まで読み、証拠ポインタをたどり、スポットチェックする。GitHub はコミットされた TSV をテーブルとしてレンダリングする。`column -s$'\t' -t decisions.tsv` はそれをターミナルでレンダリングする。

## このスキルを構成する

他のスキルは、監査証跡を発明するのではなく、ここにルーティングする。名前で参照し、フォーマットを所有させる。カラムを再述しない。
