# 振る舞いをテストせよ、実装ではなく

テストとは、コードのユーザーがインターフェースを通じて観測できるものについての主張である: 戻り値、エラー、彼らが読み返せる状態、外部システムへの作用。プライベートヘルパー、内部呼び出し順序、中間データは実装である。

各テストを2つの想像上の編集に照らして評価せよ:

- **振る舞いを壊す**（誤った値、スキップされた、または二重に発生した作用）。それでもテストが通るなら、何も証明していない。典型的な原因は、緩いアサーション、テスト対象のコードが計算した期待値、テスト自身が構築したデータへのアサーションである。
- **内部を変える**が、観測可能な結果はすべて保つ。テストが失敗するなら、それは実装に固定されている。

最初の編集を捕まえ、2つ目を生き延びるテストを残せ。残りは書き直すか削除せよ。公開インターフェースを通じて具体的な入力でコードを駆動し、要件から期待値を導出せよ。外部サービスが受け取るものは振る舞いである。内部ヘルパーへの呼び出しはそうではない。「これは決して起きない」は、それが起こるケースと対にせよ。呼び出し元が分岐対象とするエラー型をアサートせよ。メッセージではなく。
