# 数値を説明せよ

- **実行前に判断基準を書く。** それを変えうる結果と、ノイズフロアを明示する。実行間の広がりが効果より大きければ止める。
- **「なぜ倍にならない？」と問う。** 実行中に取ったプロファイルやカウンタから、結果を律速しているリソースまたはコードパスを特定する。コードを読んだ上での推測は律速要因ではない。
- **その数値が他に何を測っている可能性があるか列挙する**（エラー、スキップされた作業やキャッシュされた作業、実行されなかったコード、チューニングされていない対向、ノイズ、重要でないほど小さな部分）、そしてそれぞれを証拠で排除する。
- **実行回数、広がり、律速要因を数値とともに保持する。**

性能の数値については、[benchmark-checklist](../benchmark-checklist/SKILL.md) スキルを実行する。eval結果については、各実行がタスクを遂行したか、試行とモデルをまたいで差が維持されるか、そのシナリオに意味があるかを問う。
