# 結果志向の実行

滑らかな中間状態を保つことよりも、意図された検証可能な最終状態を最適化せよ。

**理由:** すべての中間ステップを完全に安定に保つと、しばしば一時的な互換コードが生まれ、それが長期的な負債になる。目標アーキテクチャに収束させ、明示的な検証境界で正しさを証明せよ。

**中核ルール:**
- 過渡期の安定性よりも最終状態の整合性を優先する
- 中間期の破損は、計画され、範囲が限定され、可逆であるときは許容される

**ガードレール:**
- 明示的なフェーズ境界を持つ計画された書き直しと移行にのみ使用する
- 一時的な破損がどこで許容されるかを宣言する
- 移行中は、実際に触れている領域に対して高シグナルのチェックを維持する
- プラン完了時には静的・ランタイム双方の完全な検証を求める
