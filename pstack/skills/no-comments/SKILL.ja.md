# No comments

Comment Sicko を起動する。受け入れられた発見に基づいて行動する。

Comment Sicko の新鮮な視点に従う。

## スコープ

呼び出し元のファイルまたは diff を使う。それ以外はベースブランチ（デフォルト `main`）に対する現在の diff を、ワーキングツリーを含めて使う。

## ステップ

1. `subagent_type: "comment-sicko"` で `Task` を起動する。スコープを渡す。**poteto-mode** スキルの Subagents セクションに従って、各サブエージェントの推論レベルをジョブに合わせて選ぶ。そのルールを再述しない。
2. レポートと diff を検査する。アプリケーションコードの編集、スコープエスケープ、例外保護された削除、誤って述べられた `MUST KILL` の理由、および保持された意図的なコードを有罪として扱うフラグを拒否する。我々のコード上の驚きに関する再形成フラグは依然として実行可能である。それらのコメントを復元しない。保持は、変更できないものに関する証拠がある場合のみ生き残る。見落とされたスコープ付き lint と TypeScript サプレッションを監査する。正確性または安全性のサプレッションは実行可能な `MUST KILL` のままである。削除は、正確な例外とスコープ付き証拠がある場合のみ復元する。薄い `IMPORTANT` や `do not remove` の kill や keep を受け入れる前に、そのシンボルを追跡するか `/why` を実行する。kill が曖昧な場合、復元しない。keep が反駁されるか依然として曖昧な場合、削除する。失敗を名付けて、拒否された 1 つのレポートを元に戻して再実行する。2 つ目を拒否する場合、オープンとして報告し、`/no-comments` を失敗させる。
3. 死んだパスを削除する、パラメータを削除する、実際の API を使うことで、些細な受け入れられたフラグを直接修正する。修正が形を必要とする場合、受け入れられたセットと周辺コードに対して `/architect` を一度実行する。スケッチで停止する。Architect は形を作る。ステップ 4 が実装する。
4. スコープ内の最小の根本原因修正を実装する。すべての名付けられた回避策を削除する。根本原因がスコープ外の場合、最小のスコープ内修正をランディングし、残りをオープンとして報告する。**principle-fix-root-causes** と **principle-redesign-from-first-principles** スキルは意図のみを導く。どちらもフェンスを広げることや、その外のインスタンスを修正することを許可しない。症状のガードを付け加えない。
5. 制約コメントは `do not remove`、`do not change wording`、または `talk to X before changing` と言う。変更できないものに関する keep はそのままにする。最も安価なスコープ内の型、ランタイム、テスト、または CI lint を提案する。インタラクティブな承認を待つ。非対話型および eval は呼び出し元の事前承認を必要とする。承認されたらエンコードしてから削除する。それ以外は削除し、制約をオープンとして報告し、スコープ外の作業をスケッチする。
6. 削除数、復元されたコメント、再実行、architect のスケッチ、修正、エンコーディングの提案、エンコーディング、強制されていない制約、およびその他のオープンな作業を報告する。
