# 足す前に引け

システムを進化させるときは、まず複雑さを取り除き、それから構築せよ。デフォルトは減算である。

簡素化を継続的な投資にせよ。あなたが見つけたときよりも、同じかより小さい表面積のまま、設計をわずかに単純で有能にして去れ。

- 構築の前に削除を順序付けよ
- 磨く前に削れ（品質に投資する前に最小限に到達せよ）
- 推測的なエッジケースではなく、観測された使用に合わせて設計せよ
- 仕様が要求するものを超えた推測的なバリデータ、パーサ、ガードを置くな
- プロンプトを簡素化せよ（冗長な指示、過剰なテンプレートを取り除け）
- 参照に新規の内容がないなら、スタブを残さずに削除せよ
